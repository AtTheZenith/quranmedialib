# v4.1.1 — Rich Text Overhaul & Presets Solidification

## Highlights

- **Rich text parser rewritten to the modern tag spec** (`#b|i|bi#<hex6|hex8>#text#`) — legacy format (`#b#Bold#b#`, `#ff0000#Red#ff0000#`) is fully removed
- **Presets solidified** — v3 layout parity restored across all 9 aspect-mode combinations (`landscape`/`story`/`square` × `default`/`arabic`/`translation`)
- **Bold and italic rendering actually applied** — bold was parsed but never drawn; italic ignored the configured italic font path
- **New `ignore_non_token_hashtags` option** — warns on stray `#` not forming a valid tag (default), or silently renders them as literal text while still parsing valid tags
- **332 unit tests pass** (was 322)

## New Features

- `TextConfig.ignore_non_token_hashtags` (`bool`, default `False`) — when `False`, a `#` character not regexed into a rich-text tag logs a `WARNING` that names the malformed tag itself, restates the expected `#<style>#<color>#text#` syntax, and points to `ignore_non_token_hashtags` to suppress it. When `True`, the warning is suppressed and stray hashtags render as literal text; valid tags are still parsed in both modes.
- Pairwise pixel-identity tests guarantee no style silently renders identically to another: normal, bold, italic, and bold-italic are each compared by SHA-256 of their raw pixel bytes and must all be distinct. A dedicated test asserts a pixel exactly matches the tag color.

## Bug Fixes

- **Bold never rendered**: `simulate_bold` was parsed and stored on each styled word but was excluded from the batch styling key, so it was never applied at draw time. The batch style key now includes `simulate_bold`, and `_flush_batch()` applies the stroke simulation.
- **Italic hardcoded the font path**: the italic renderer did `.replace(".ttf", "_italic.ttf")` instead of honoring `config.italic_font_path`. Custom italic fonts are now respected.
- **Legacy rich-text format accepted**: `_RE_RICH_TAG` previously tolerated the old `#style#text#style#` and `#hex#text#hex#` forms. The parser now accepts only the modern, mandatory-closing-tag spec: `#([bi]+)#([0-9a-fA-F]{6}|[0-9a-fA-F]{8})#([^#]+)#`. Six-digit (24-bit) colors gain an opaque `ff` alpha; eight-digit (32-bit) colors are used verbatim.
- **Combined bold+italic** (`bi`) now applies the italic font and stroke simulation together instead of picking one style.
- **Dead code removed**: `_RE_STRIP_TAGS` and associated strip logic removed.
- **Isolation output modernized**: `format_isolation_text()` and `IsolateWordsWorkflow` now emit per-word modern tags (`#b#00000000#word#` for transparent non-target words), and the default highlight style is the gold `#b#ffd700ff#` matching `TextConfig.highlight_color`.

## Validation Expansion (relative + absolute)

- **New granular golden scenarios** mirroring the rich-text unit tests, so `check compare vA vB` attributes pixel changes precisely:
  - `timage_styles_italic` — `#i#00ff00ff#Italic Green#` (italic font + green)
  - `timage_styles_bolditalic` — `#bi#0000ffff#Bold Italic Blue#` (combined style + blue)
  - `timage_color_six` — `#b#ff0000#Red 6-digit#` (24-bit color alpha expansion)
- **Golden coverage for the image primitives** (`modules/image.py` `color`/`pad`/`glow`) — these standalone utilities had no call sites in the render pipeline and zero golden refs. New `image`-module scenarios build a real rendered word then apply the primitive:
  - `image_color` — luminance colorization of a word
  - `image_pad` — padding of a word
  - `image_glow_default` — `glow()` default params (balanced, RGBA composite path)
  - `image_glow_quality` — 3 pages, `glow()` at fast/balanced/quality (the brightness-analysis core)
  - `image_glow_comparison` — original + fast + balanced + quality side-by-side
- **Golden coverage for Quranic stop-sign page breaks**: `vimage_stop_signs` renders with a stop-sign word mid-page under a 2-row limit; the harness now supports multi-page `rows_per_page` module scenarios. Verified sensitive: removing the stop-sign adjustment changes 8000 pixels.
- **Ref-free stop-sign guard** (`test_vimage_stop_sign_render_sensitive`): the golden ref for stop-sign page breaks only runs locally (refs are git-ignored), so a matching always-run unit test now renders the scenario without refs and asserts the adjustment shifts page-1 pixels — verified to fail when the adjustment is disabled, so CI catches the regression.
- **Harness** `_render_module_pages` extended: `module="image"` op dispatch + multi-page vimage loop (fixes `get_page_chunk` `consumed` as relative-to-`pos`).
- **`check test --unit` is now ref-free** — it excludes `tests/test_validation.py` (which needs git-ignored golden images), so the CI/pre-push unit gate passes on a fresh checkout. Golden validation stays local via `check test`.
- **Two-layer validation philosophy documented** in `AGENTS.md` §17.5: relative unit assertions (pairwise-distinct hashes, ink, color) catch style-vs-style regressions; absolute golden refs catch corruption that preserves distinctness (e.g. tofu in every mode). Unit tests now pair every relative render check with an absolute bound, and assert render determinism (`img.tobytes()` identical across runs) — the golden system's core assumption.
- **Unit test additions**: `test_draw_all_styles_pairwise_distinct` gained a non-blank absolute guard; new `test_draw_timage_deterministic`.
