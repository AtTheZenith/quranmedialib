# v4.2.0 — Balancing-Mode Paragraph Layout & Input Hardening

## Highlights

- **`BalancingMode` — four paragraph-balancing solvers** behind one switch: `FORWARD` (greedy max-fill), `SMOOTH` (global flattest pyramid, default), `KNUTH_PLASS` (optimized quadratic-slack DP), and `TEX` (micro-optimized faithful TeX port).
- **Greedy is the unconditional fallback.** Whatever solver is chosen, an infeasible result (`None`) is replaced by a valid greedy layout and logged with a reason plus a short source-text preview; a layout is only reported infeasible when greedy itself cannot satisfy it.
- **Input hardening.** Text inputs are bounded before measurement (`MAX_TEXT_CHARS`, `MAX_TEXT_WORDS`) and rendered canvases are clamped to `MAX_CANVAS_DIMENSION`, closing a decompression-bomb/OOM vector from an over-wide single word.
- **Font-faithful measurement.** Simulated-bold strokes now reserve their ink width in each word's advance, so bold text no longer clips its right-most glyph.

## New Features

- `BalancingMode` enum (`FORWARD`/`SMOOTH`/`KNUTH_PLASS`/`TEX`, default `SMOOTH`) exposed on `TextConfig.balancing_mode` and `VerseConfig.balancing_mode` (accepts the enum or its lowercase string). Deprecated alias `balanced_line_smooth(smooth=True/False)` still maps to SMOOTH/FORWARD for backward compatibility.
- `MAX_TEXT_CHARS` (10,000) and `MAX_TEXT_WORDS` (1,000) exported at package level; `get_timage` rejects over-limit input with `ValueError` before any measurement.
- Canvas cap: `get_timage` clamps any resulting canvas to `MAX_CANVAS_DIMENSION` and logs a `WARNING`, so a single word wider than the container (placed on its own line) cannot allocate an unbounded image.

## Bug Fixes

- **Simulated-bold clipping**: bold text drawn with a 1px stroke was measured with a plain-font advance, clipping the right glyph. Bold words now add `2 ×` the stroke width to their measured width (shared `_SIMULATE_BOLD_STROKE_WIDTH` constant keeps measurement and draw in sync).
- **Unbounded canvas from an over-long word**: an over-wide word escaped `max_width` (it belongs on its own line) and could drive the output image past any cap; the canvas is now hard-clamped.
- **Knuth-Plass window computation**: a float-division/`range()` interaction at a large container width was corrected.

## Internal Notes

- `text_layout.py` break-index contract documented uniformly (`[]` single line, `None` infeasible); `FORWARD` dispatches straight to greedy; the three linear solvers share one fallback path with a diagnostic reason (`word too long` → warn; benign primary-solver infeasibility → `debug`).
- `knuth_plass.py` adds guarded worker budgets (`_FAITHFUL_MAX_ACTIVE`, `_FAITHFUL_MAX_SCANS`) so the faithful TeX twin aborts to greedy rather than spinning on pathological inputs.
- Golden references regenerated for this version (bold-width and greedy-fallback output changes).

## Validation

- `uv run -m quranmedialib.check test` — all scenarios + unit tests pass, no regressions.
- `uv run -m ruff check src/ tests/` — clean.
- New unit tests: balancing per-mode layout boundaries, greedy-fallback warning *and* word-too-long paths, text-preview truncation, character/word limit rejection, and canvas-clamp on an over-long word.
- New regression benchmark (`test_balance_solver_regression_benchmark`): times the greedy `FORWARD` path (linear) and the `SMOOTH` quadratic DP, asserting generous absolute and relative-scaling bounds so an order-of-magnitude cost regression in either solver fails loudly while staying robust to machine speed.
