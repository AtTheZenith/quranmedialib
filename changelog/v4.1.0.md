# v4.1.0 — Al-Baqarah Validation & Performance Stabilization

## Highlights

- **`quranmedialib.check` module** — automated pixel regression suite with canonical scenarios, cross-version comparison, and performance benchmarks
- **Full Surah Al-Baqarah (286 verses) stress test** at 1080p landscape as the primary validation scenario
- **Memory regression fixed** — peak main-process RSS dropped from 3,700MB→48MB by switching from list collection to streaming generator (`_iter_pages`)
- **Performance regression fixed** — Al-Baqarah benchmark restored to 6.99s (within v3 baseline) by replacing `max_batch_size=5` with natural chunking and throttling memory checks to every 10 verses
- **322 tests pass in 53s** (was 399s under regression)

## New Features

- `check` module with six subcommands:
  - `list` — enumerate canonical validation scenarios
  - `run` — quick pixel validation (no benchmarks)
  - `test` — full suite: pixel validation + benchmarks + unit tests
  - `update --version X.Y.Z` — (re)generate reference images
  - `compare vA vB` — cross-version pixel diff
  - `benchmark` — standalone performance benchmarks
- Streaming page iteration (`_iter_pages()` generator) for validate & update paths
- File-based benchmark mode — `benchmark_scenario()` uses `output_dir` + page counting to avoid 3.8GB IPC deserialization
- Natural chunking in `map_batches()` — `ceil(tasks / workers)` replaces hardcoded `max_batch_size=5`
- `_count_pages()` method on `VerseRangeWorkflow` for O(1) page counting without materializing images
- **`_bytes_mode_max_batch()`** — module-level adaptive batch cap for the bytes IPC path. Prevents per-worker OOM by bounding `batch_results` accumulation based on frame dimensions and per-process 256MB limit. Caps at 8 verses at 1080p, 2 at 2160p.

## Bug Fixes

- **OOM in validate/update paths**: `render_scenario()` accumulated all pages in memory before processing. Fixed by `_iter_pages()` generator yielding pages one-at-a-time.
- **Slow Al-Baqarah benchmark** (22.8s per run, 399s total): Two root causes:
   1. `max_batch_size=5` caused 58 IPC rounds instead of natural chunk count (~12). Fixed with `ceil(tasks/workers)`.
   2. Per-verse `get_current_rss_mb()` + `worker_heartbeat()` added ~0.5s overhead over 286 verses. Throttled to every 10 verses.
- **Dead code**: `_compute_pixel_hash()` removed (unused after benchmark refactor)
- **SurahWorkflow duplicate workflow creation**: `_iter_pages` was creating two `SurahWorkflow` instances per call — consolidated to single `_build_workflow()`.
- **Memory limit regression**: `DEFAULT_PROCESS_LIMIT_MB` was raised 256→768MB, hiding regressions. Reverted to 256MB. Per-worker memory stays at ~100MB during file-based rendering — the 768MB ceiling would let leaks slip through undetected.
- **Spurious aggregate memory warnings**: Background-thread `MemoryMonitor` logged ERROR every 0.5s during parallel Al-Baqarah rendering. Removed entirely. Aggregate RSS runs at ~700MB (8 workers × ~100MB), well under the 2048MB computed cap. Per-process `worker_heartbeat()` is the real enforcement.
- **`worker_heartbeat()` now crashes directly**: Removed try/except wrapper — uncaught `MemoryLimitExceededError` propagates from the worker and kills the pipeline cleanly instead of logging a soft warning and half-raising.
- **Duplicate `clear_rendering_caches()` in memory.py**: Second definition silently overrode the first. Deduped to one function.
- **Dead `check_aggregate_memory()`**: Removed — it was no longer called after removing aggregate checks from `ParallelRenderer.map()`.
- **Pillow deprecation**: `Image.getdata()` in `test_vimage.py:192` will break in Pillow 14 (Oct 2027). Replaced with `tobytes()` comparison.

## Internal Changes

- `_PoolManager` executor caching: no longer causes test isolation failures (memory pressure was the root cause, not caching itself)
- `perf.json` benchmark artifact generated under `.bm/`
- `.gitignore` updated with `.bm/` pattern
- Reference images: 473 Al-Baqarah PNGs + 6 module-level scenarios + `scenarios.json` + `sha256sums`
- Python 3.13 `max_batch_size` kwarg in `map_batches()` for optional capping
- `ParallelRenderer.map()` no longer accepts `use_monitor` or `memory_limit_mb` — removed unused API
- `_bytes_mode_max_batch()` — adaptive batch cap for bytes IPC path (module-level, imported from `verse_range`)
- `worker_heartbeat()` hardened: no try/except, uncaught exception crashes the worker
- 10 new tests: `worker_heartbeat` unit tests (10), `_bytes_mode_max_batch` golden tests (5), `_handle_output` bytes path tests (3), bytes IPC integration tests (2)
