# v5.0.0 — Spatial Sidecars & Dual-Hash Geometry Validation

## Highlights

- **Spatial sidecars (`schema: spatial-1`)** — file-writing workflows now emit a deterministic JSON sidecar beside every PNG. Each sidecar records the page's exact layout: per-word bounding boxes with their `index`/`class_type`, row geometry, verse number placement, and the translation paragraph's box, `exceeded_bounds`, and raw rich-text `text`. Geometry is serialized from the *same layout state the compositor draws*, so the sidecar agrees with the pixels by construction — never re-parsed from rendered output.
- **`emit_sidecar` is explicit opt-in** (default `False`) on `VerseRangeWorkflow` / `SurahWorkflow` `get_iterator` kwargs. Requires `output_dir`; bytes mode is untouched.
- **Harness dual-hash validation** — `quranmedialib.check` now hashes sidecar geometry per page alongside the pixel hash during both `update` and `validate`. A subtle 2px layout shift that passes the pixel diff (rare) now fails the geometry hash, closing the second axis of regression detection.
- **The Agent Loop contract** — page sidecars are a pure function of layout state (no timestamps, no config snapshots, no fonts, no absolute paths). An external agent can read structured geometry, adjust layout *parameters*, and re-invoke the deterministic core. Per-page sidecars are keyed in **chronological schema order** (not sorted).
- **Per-task `task.json` (`schema: task-1`)** — each render task also writes a documentation sidecar at the output root recording the process: workflow type, surah/ayah range, `annotate`/`separate_translations`/`parallel` flags, resolved frame/word/verse/text configs, database filepaths, and fonts. It is *not* hashed by validation — it documents a specific machine's run (absolute paths expected).

## New Features

- `emit_sidecar` kwarg on `VerseRangeWorkflow.get_iterator` and `SurahWorkflow.get_iterator`: when `True` (with `output_dir`), each `page_N.png` gains a sibling `page_N.json` written through the same bounded async-I/O path inside the worker processes.
- `modules/sidecar.py`: `build_sidecar` / `build_task_sidecar` / `serialize_sidecar` / `sidecar_filename`, emitting the `spatial-1` / `task-1` contracts — integer page-relative coordinates, ordered keys, UTF-8 Arabic, deterministic bytes.
- **Translation `text` in the page sidecar** — the `translation` record now carries the raw rich-text translation string alongside its geometry.
- **Per-task `task.json`** — `_process_range` writes one `task.json` (`schema: task-1`) at the output root when `emit_sidecar=True`, via new `DatabaseManager.get_database_configs()`. Includes workflow identity, resolved configs, database filepaths, and fonts.
- `WordItem.index` and `WordItem.class_type` fields: `index` is the word's 1-based position in the surah/verse sequence (matching `surah:verse:word` keys); `class_type` discriminates `"word"` from `"verse_number"`. Combined annotation batches emit **one record per source word** (own `index`/`text`/`wbw`) sharing the batch's pixel box.
- `annotate_words` / `annotate_words_with_texts` gain `return_batch_map: bool = False` — additive contract returning the `list[(start_index, count)]` batch structure without changing existing callers.
- `async_image_saver.save_data(path, payload)`: a generic data-writer sibling sharing the executor + bounded semaphore, so one saver handle writes both images and JSON.
- Internal `timage._render_timage` returns `exceeded_bounds` (a line was skipped by the max-height clamp), surfaced in the sidecar's translation record.
- **Harness:** two new canonical scenarios appended only (`surah_kawthar_sidecar`, `range_kawthar_sidecar`); `perf.json` scenario entries persist per-page `sidecar_hashes` when present (backward compatible with older refs); `ValidationResult.sidecar_mismatch` reported in `check run`/`check test` JSON output and the terminal report.

## Bug Fixes

- **Latent verse.py annotation/text misalignment** (found while threading the batch map): `all_text` was built from unbatched `verse_words` while `annotated_images` could be shorter after wbw batching, desynchronizing the two lists. Now driven off the batch map.
- **Translation sidecar position agreed with the placement rect, not the paste box** — in `keep_bottom`/centred modes (e.g. landscape/default), the `translation` node's recorded `position` used the raw `place_rect`, but the image was actually pasted lower (bottom-anchored) and centred. `Frame.layer_at` is now the single authority on paste position: a custom record declaring a `position` slot has it completed with the actual paste box, so geometry agrees with pixels by construction. The `position: None` placeholder preserves the spec's chronological key order (`bbox, position, exceeded_bounds, text`).

## Internal Notes

- **Modular self-describing sidecar emission** — each `Layerable` now owns its sidecar record: `VImage.layer()` accepts an optional `sidecar_sink` and emits its own fully-built `vimage` node (block box + per-row boxes + flat word records) straight from the placement loop; `Frame` collects these nodes into `sidecar_layers` when `collect_sidecar=True` (zero-cost otherwise, default unchanged). `build_sidecar` is now a thin assembler over the collected `layers[]` that applies only emission-time concerns the renderer must not know: the wbw join and combined-batch expansion. `geometry_sink`/`block_sink` callbacks and `WordItem`-level geometry threading were removed. Custom `Layerable` classes self-describe by accepting `sidecar_sink` in `layer()` and emitting their own `class_type` node.
- `schema: "spatial-1"` is versioned independently of the library; consumers key off `schema` alone. A universal-contract change bumps to `spatial-2`; type-declared metadata additions do not. The `rows`→`layers[]` emission change lands against `spatial-1` (the `-1` suffix is provisional on this unreleased fork; version locks only at branch finalization).
- Sidecars are **not** produced in bytes mode (`use_bytes`) — internal IPC optimization with no consumer. `VerseWorkflow` / `IsolateWordsWorkflow` never write files and remain out of sidecar scope (documented exclusions).
- README demo-gallery images moved off stale GitHub `user-attachments` URLs to live hosted assets.

## Validation

- `uv run -m quranmedialib.check test` — all scenarios + unit tests pass, no regressions.
- `uv run -m ruff check src/ tests/` — clean.
- Dual-axis proof in `test_validation.py`: a 2px `x += 2` shift of a word fails the geometry hash while every page keeps `diff_pixels == 0` — the second axis catches what pixels miss.
- Golden refs regenerated for this version: 535 PNGs, existing 35 scenarios byte-identical; 2 new sidecar scenarios carry `sidecar_hashes` in `perf.json`.
- 20 new unit tests across phases (WordItem fields, batch map, geometry sink, `save_data`, sidecar serializer, task sidecar, sidecar end-to-end, harness dual-hash).
